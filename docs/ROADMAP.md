# Project-YYJian 整體工程藍圖(2026-07-15 制定)

> 目標:把月月做成「真正的 agent + 聊天社交優勢」的完整工程,直到達到可公開上 GitHub 的水準。
> 原則:穩定第一、每步可驗證、模型負責智能而腳手架負責安全、聊天語感是差異化核心不許退步。

## 現狀基線(已完成,作為出發點)

- v3 runtime:單寫者事件迴圈 + 目標契約工作流 + 許可控制,「不准假成功」全鏈路(證據可見、防捏造 grounding、變更未完不交差)。
- 模型定案:聊天 MiniMax-M2.5 / 任務 DeepSeek-V4-Pro(A/B 實測便宜模型崩,不再換)/ 視覺 Qwen-VL。
- 語感:voice_contract 單一事實源 + 輸出閘;人設雌小鬼+軟反差,已過真機校準。
- 質量網:212 條測試 + eval 套件(Tier 1 免費確定性 / Tier 2 真生成+評審)。
- 差距電池:6 任務 3/6 → 穩定 4-5/6,剩餘變異是 V4-Pro 規劃隨機性,非腳手架 bug。

## 已知債務(計劃要解的)

1. **啟發式規則寫死了智能**:526 條禁語表 + ~30 個 marker 清單 + 關鍵字路由,越修越苦(打地鼠結構)。
2. **沒有長期記憶**:只有 20 輪環形緩衝 + profile.json,記不住上週的事——陪伴屬性最大缺口。
3. **規劃隨機性**:同一任務跨輪過/不過,V4-Pro 有時把三步任務規劃成一步。
4. **許可 UX 粗糙**:罐頭「這一步需要你點頭」會重覆出現;任務模式偶爾漏粵語/日文字。
5. **主動性弱**:presence 引擎只有基礎節律,不會記住「主人說等下回來」然後跟進。
6. **未達公開標準**:真實 token 在 .env、個人數據混在 repo、文檔面向自己不面向外人。

## Phase 1:把智能還給模型(1-2 輪)——治「越修越苦」的根

**目的**:規則層只做安全網,判斷交給模型。這是架構性反轉,砍掉最大維護痛苦源。

1. **模型路由,關鍵字降級為 fast-path**
   - 明顯情況(有媒體、貼圖、明確工具詞)仍走關鍵字秒判(零成本零延遲);
   - 灰色地帶改由 MiniMax 用 ~100 token 的微型路由提示判斷(一次幾厘錢);
   - 關鍵字誤判史(設定/菜單、用指令查版本)全部變成路由 eval 案例鎖住。
2. **凍結 526 條禁語表,啟動瘦身**
   - 立即凍結:只減不加(規則寫進 CLAUDE/文檔);
   - 用已建好的 eval Tier 1 做回歸網,分批砍表(每批砍後跑 eval,好句誤殺率不升才續砍);
   - 替代機制已存在(`_regenerate_compliant_chat_reply` 模型自檢重寫),把它變成主通道。
3. **許可請求全面模型化**
   - 罐頭「這一步需要你點頭」只准出現在模型連續兩次生成失敗後;
   - 修「同一輪重覆罐頭」問題(生成失敗要帶上下文重試,不是直接掉兌底)。

**驗收**:路由 eval 全綠;禁語表條目數下降 ≥30% 且 Tier 1 好句零誤殺;電池許可對話裡罐頭句占比 <20%。

**進度(2026-07-16)**:✅ 灰區 LLM 路由上線(route_llm.py,YUEYUE_LLM_ROUTING=1,真機煙測通過);
✅ 禁語表凍結(ratchet 測試 143/179 上限,只准減);✅ 罐頭句治理——_compose_owner_voice、
問候/短句生成全部改為「帶具名批評重試一次」才准掉兌底池,禁語命中從「丟棄→罐頭」變成
「自我修正信號」。註:實測後判斷「物理刪表」優先級下降——命中已不再產生罐頭輸出,
留著的表是免費的檢測器;30% 刪減目標改為機會性執行。

## Phase 2:長期記憶層(2-3 輪)——陪伴屬性的能力躍升

**目的**:月月記得住「上週你說過什麼」,聊天引用共同經歷——這是陪伴類 agent 的殺手級能力,也直接放大聊天社交優勢。

**設計(三層)**:
1. **情節記憶(episodic)**:每日對話由 MiniMax 做廉價摘要(誰說了什麼重要的事、情緒、約定),存 JSONL,帶時間戳。
2. **語義事實(semantic)**:從對話抽取穩定事實(喜好、人物、習慣、紀念日),寫入結構化存儲,與現有 profile.json 合併演進;每條帶來源和置信度。
3. **檢索注入(retrieval)**:用 SiliconFlow 的 `BAAI/bge-m3`(便宜到忽略不計)做 embedding;每個聊天回合檢索 top-k 相關記憶,壓縮注入上下文(嚴格限額,別撐爆 prompt)。

**安全與誠實**:
- 記憶寫入有質量閘(不存猜測、不存模型幻覺;寫入前對照證據);
- 「你記得X嗎」答不出就誠實說忘了(現有規則保留),檢索到就自然引用;
- 主人可糾正/刪除記憶(「你記錯了」→ 修正機制)。

**驗收**:新 eval 維度「記憶引用」——隔日測試:前一天提過的事,今天問能自然引用;誤引用率為零(寧可說忘了)。

**進度(2026-07-16)**:✅ 核心已建成部署(yueyue_v3/memory.py):情節+事實雙層、embedding 內嵌
JSONL、餘弦檢索、蒸餾器帶主人原話 grounding 閘(引不出原話的「事實」直接丟棄);讀路徑
ContextCompiler 注入帶日期+誠實對沖的記憶注;寫路徑 main.py 回覆送出後背景蒸餾(每 12 輪,
YUEYUE_LTM=1);任何失敗降級為「無回憶」,聊天永不因記憶壞掉;forget() 支援主人糾正。
10 條離線測試。⬜ 待辦:充值後真機驗證 bge-m3 檢索與隔日引用;「記錯了」對話式糾正接線;
記憶引用 eval 維度。

## Phase 3:任務可靠性硬化(1-2 輪)——把 4-5/6 推向穩定 6/6

**目的**:規劃隨機性是模型上限,但可以用工程手段夾住。

1. **黃金規劃範例(few-shot planning)**:給 planner 塞 4-5 個常見任務形狀的標準規劃(數數/讀檔/寫檔/搜尋/多步變更)——直接打隨機性,成本極低。
2. **契約自修復迴路強化**:規劃驗證失敗 → 帶具體結構性反饋重規劃(已有雛形,補齊反饋質量)。
3. **完成後自查(post-completion verify)**:任務標記完成前,廉價模型對照 objective 檢查 outputs 是否真的回答了問題(防「答非所問」類完成)。
4. **電池進 CI 習慣**:每次大改後跑一輪(6 任務 ~¥1),分數寫入基線追蹤。

**驗收**:電池連續三輪 ≥5/6;罐頭結果句(「找到了,結果是」)被模型自然表達替代。

**進度(2026-07-16)**:✅ 黃金規劃形狀(5 個常見任務族的標準規劃進 planner 提示);✅ 完成後自查(YUEYUE_TASK_POSTCHECK=1,答非所問→誠實卡點,只對真 provider 生效)。⬜ 電池驗證輪(等充值)。

## Phase 4:主動陪伴智能(1-2 輪)——建立在 Phase 2 之上

**目的**:從「被動應答」到「像人一樣主動」——這是聊天優勢的第二級放大。

1. **承諾跟進**:對話裡的約定(「我等下回來」「明天考試」)寫入記憶並帶觸發時間,presence 引擎到點自然跟進(「考完了嗎?」)。
2. **節律學習**:從歷史推斷主人作息,presence 檢查頻率/時段自適應(安靜時段已有,升級為學習型)。
3. **情緒連續性**:昨天主人情緒低落,今天開場自然關心(靠情節記憶,不靠規則)。
4. **貼圖時機**:社交層用記憶上下文選貼圖(現在只看當回合)。

**驗收**:presence eval 場景(約定跟進/情緒延續)通過;主人主觀「像真人」評分。

**進度(2026-07-16)**:✅ 承諾跟進(蒸餾抽取約定+due 日期+主人原話 grounding,到期由 presence 以最高優先跟進,消費式只提醒一次);✅ 情緒連續性(開場問候時浮現昨日情節)。⬜ 節律學習與記憶化貼圖時機——判斷為邊際收益,延後。

## 執行紀律(每一步都遵守)

- 每個 Phase 結束:`pytest tests_v3` + `eval_suite.py` + 官方閘門全綠,live bot 重啟驗證,才進下一 Phase。
- 聊天語感是紅線:任何改動導致 Tier 1 好句誤殺 → 立即回滾。
- API 成本紀律:電池/Tier 2 只在 Phase 收尾跑,不拿來調參碰運氣。
- 文檔與記憶同步:每 Phase 完成更新本檔勾選框 + ARCHITECTURE/RUNBOOK。

## 順序邏輯(為什麼是這個順序)

Phase 1 先做是因為它砍掉維護稅,之後每一步都省力;Phase 2 是最大能力躍升且 Phase 4 依賴它;
Phase 3 獨立可插隊(如果任務掉鏈子變頻繁就提前);Phase 5 必須最後(公開標準是終態不是過程)。
